# Staff Engineer — 技术机会发现机制

**目标：** 每周投入 4 小时，发现高价值技术方向，形成 Proposal，争取明确的 Ownership。

## 一、方法

每周从以下四个来源搜集技术问题：

| 来源 | 关注什么 | 可能形成的项目 |
|---|---|---|
| 竞对 | 新功能、新架构、性能突破 | 竞品能力差距分析 |
| 生产系统 | 慢请求、资源浪费、故障、性能瓶颈 | 系统级性能优化 |
| 内部研发 | 重复劳动、反复修 Bug、跨团队依赖 | 工程效率或架构治理 |
| 技术趋势 | 新客户端、新协议、新实现 | 技术预研与架构演进 |

### 每周 Checklist（4h）

- [ ] **机会发现（1h）**：收集潜在技术方向
- [ ] **问题分析（1h）**：调研现状，寻找数据和证据
- [ ] **方向评估（1h）**：比较业务价值、影响范围、个人匹配度和 Ownership 空间
- [ ] **Proposal（1h）**：选择一个方向，形成提案并推动讨论

**每周产出：** 至少发现 1 个值得研究的方向，完成 1 份半页 Proposal。

## 三、本周提案

**方向名称：**

### 1. Why — 为什么这个问题对团队重要？

- 解决什么业务或技术问题？
- 为什么现在值得做？

### 2. Evidence — 有什么证据说明值得解决？

- Benchmark / 线上指标 / 竞品动态 / Issue
- 当前方案的主要问题或瓶颈

### 3. Impact — 预期收益是什么？

- 可量化指标：吞吐、延迟、成本、稳定性、研发效率等
- 影响范围与验收标准

### 4. Ownership — 我希望承担什么责任？

- **Scope：** 负责哪些系统、模块或技术方向？
- **Authority：** 希望拥有哪些技术决策权？
- **Deliverables：** 设计、PoC、实现、Benchmark、落地
- **Resources：** 需要哪些资源与团队支持？

### Next Steps

- [ ] 与 Leader / 相关 Owner 对齐优先级
- [ ] 确认 Ownership、资源与验收标准
- [ ] 确定下一步行动和时间节点

---

**核心原则：** 不只是发现问题和完成任务，而是主动定义高价值问题、争取 Ownership，并推动成果落地。
